示教-复现（三）：三融合行驶与丢线兜底

机器人 ROS2

三融合行驶与它的边界：巡线、标签、里程计按优先级降级；巡线受光照限制，长距方案暂停，改短距直行掉头，含关键源码

标签：
状态机 巡线 里程计
发布于 2026年11月22日

前言 ​

伺服负责最后 1 m，长距离移动靠行驶层。地面红线会被反光、阴影、异物打断，相机视野里还有一片固定红区，所以难点在跟丢之后怎么办。

一、三种信息源各有盲区 ​

信息源能给什么盲区
巡线横向偏差、全程连续不控航向，瞬态误差按剩余距离放大；丢线后无位姿
标签三轴位姿，绝对基准只在末端 1 m 内稳定可见（横向半视野 ±35°）
里程计距离、航向变化纯轮式，横向漂移符号会翻；掉头后航向漂约 14°

三种盲区不重叠，所以按优先级融合：巡线负责走，标签负责停，里程计负责兜底。

二、状态机：优先级 + 滞回 ​

优先级 FOLLOW（巡线）> TAG（标签航向）> DEADSTICK（里程计直行），降级要等够时间，升级要连续确认：

text
WAIT_START ──首帧检出──▶ FOLLOW
FOLLOW ──丢线 ≥ 2 s 且标签新鲜──▶ TAG ──标签丢失──▶ DEADSTICK
TAG / DEADSTICK ──连续 5 帧重新检出──▶ FOLLOW
模式横向控制典型触发
FOLLOW像素偏差比例控制 + 死区补偿正常行驶
TAG标签方位角比例控制丢线但标签可见（掉头后）
DEADSTICK里程计航向保持两者都不可用

纯逻辑部分单独抽成类，注入 (时间, 是否检出, 标签是否新鲜) 事件流，单测不需要起 ROS：

python
class LineStateMachine:
    """FOLLOW > TAG > DEADSTICK；升级要连续 N 帧，降级要等够时间。"""

    def __init__(self, lost_sec=2.0, reacq_frames=5, tag_enable=True):
        self.mode = "WAIT_START"
        self.lost_sec = lost_sec
        self.reacq_frames = reacq_frames
        self.tag_enable = tag_enable
        self._last_seen = None
        self._reacq = 0
        self.events = []                      # 每次切换留痕，便于事后复盘

    def update(self, t, detected, tag_fresh):
        tag = tag_fresh and self.tag_enable
        if self.mode == "WAIT_START":
            # 注意：这里【不】因标签新鲜就跳 TAG。
            # 起步时标签常比线先可用，立刻转 TAG 会把车带偏约 7°。
            if detected:
                self._enter("FOLLOW", t, "首帧检出")
        elif self.mode == "FOLLOW":
            if detected:
                self._last_seen, self._reacq = t, 0
            elif t - (self._last_seen or t) >= self.lost_sec:
                self._enter("TAG" if tag else "DEADSTICK", t,
                            f"丢线≥{self.lost_sec}s")
                self._reacq = 0
        elif self.mode == "TAG":
            if not tag:
                self._enter("DEADSTICK", t, "标签丢失")
            elif detected:
                self._reacq += 1
                if self._reacq >= self.reacq_frames:
                    self._enter("FOLLOW", t, f"重捕获×{self._reacq}")
            else:
                self._reacq = 0
        else:                                  # DEADSTICK
            if detected:
                self._reacq += 1
                if self._reacq >= self.reacq_frames:
                    self._enter("FOLLOW", t, f"重捕获×{self._reacq}")
            else:
                self._reacq = 0
                if tag:
                    self._enter("TAG", t, "标签重新可见")
        return self.mode

    def _enter(self, mode, t, why):
        if self.mode != mode:
            self.events.append(f"{t:7.1f}s {self.mode}->{mode} ({why})")
            self.mode = mode

两个容易忽略的细节：

WAIT 不允许直接跳 TAG。 起步时标签往往比线先「新鲜」，如果见标签就转 TAG，车会先朝标签转向，实测带偏约 7°，之后一路斜着走。改成「先等线」：只有起步宽限（10 s）内始终见不到线，才依次降级。

航向基准用圆周均值。 FOLLOW 期间把最近 1 s 的里程计航向入队，用 atan2(Σsin, Σcos) 求均值，因为直接算术平均在 ±180° 折返处会算出 0° 这种结果：

python
def circular_mean_deg(degs):
    """圆周均值：正确处理 ±180° 折返；空序列返回 None。"""
    if not degs:
        return None
    s = c = 0.0
    for d in degs:
        r = math.radians(d)
        s += math.sin(r)
        c += math.cos(r)
    return math.degrees(math.atan2(s, c))

DEADSTICK 保持这个基准；TAG 期间实时跟踪当前航向，避免标签一丢就把 TAG 的纠偏「撤销」掉。

三、巡线视觉：两个坑 ​

3.1 红色 HSV 的 0/180 环绕 ​

红色在 HSV 里的 H 大量落在 179（0 和 180 是同一处色相）。只查 H ∈ [0, 10] 时，检出靠的其实是形态学操作的副作用：erode/dilate 作用在 HSV 三通道上，逐通道取极值会把线像素的 H 拉向邻近灰度像素的 0，于是「碰巧」检出。曝光一变，这个副作用消失，整条线丢失。历史上「红线检出 0%」的根因就在这里。

修复是并集第二段 H ∈ [170, 180]：

python
LINE_COLORS = {
    "red": ((0, 100, 80), (10, 255, 255)),
    # 其余颜色不跨 0/180 边界，无需环绕段
}
LINE_WRAP = {
    "red": ((170, 100, 80), (180, 255, 255)),
}

def build_mask(hsv, lo, hi, wrap=None):
    mask = cv2.inRange(hsv, lo, hi)
    if wrap is not None:
        mask = cv2.bitwise_or(mask, cv2.inRange(hsv, wrap[0], wrap[1]))
    return mask

3.2 中远场红区污染 ​

相机中远视野有一大片红色区域（物理红源，无法处理），底边贴着检测带上沿。车开到 1.5–2 m 时，红区侵入底部采样带：

指标干净帧被污染帧
m00（白像素数）1300–21002600–4000
质心偏差±30 px+60 ~ +133 px
后果—航向累计旋转 30–40°，横向偏离 20–27 cm

两道防线：检测带从底部 200 行收窄到 150 行；再加一道单侧中位数门限：维护最近 50 个被接受帧的 m00 中位数，超过 1.6 倍就按丢线处理，被拒帧不进窗口：

python
class M00Gate:
    """单侧中位数门限：只拒高不拒低，被拒帧不进窗口（可自愈）。"""

    def __init__(self, factor=1.6, median_win=50, warmup=5):
        self.factor = factor
        self.window = deque(maxlen=median_win)
        self.warmup = warmup
        self.rejected = 0

    def accept(self, m00):
        if self.factor <= 0.0:             # 0 = 关闭门限
            return True
        if len(self.window) < self.warmup:
            self.window.append(m00)        # 热身期只查下限，避免起步被污染种死
            return True
        if m00 <= self.factor * statistics.median(self.window):
            self.window.append(m00)
            return True
        self.rejected += 1                 # 调用方按丢线处理，走 coast/DEADSTICK
        return False

1.6 这个系数是数出来的：干净帧峰值 / 基线 = 1.44，危害帧最低 / 基线 ≈ 1.7，取中间。只拒高不拒低是刻意的：末端线自然变细，m00 从 1300 掉到 300 属正常，不能误杀。

四、死区补偿要连续 ​

底盘有转向死区：角速度低于约 0.05 rad/s 轮子不转；直线同理。小误差必须抬升，但抬升本身会制造新问题：

  • 弧行步里车已经在动，此时若也抬升 w，那么两个项几乎对消的微小净指令（比如 0.02）会被放大 6 倍，接近段变成 bang-bang 震荡。抬升只允许发生在纯旋转步。
  • 抬升函数要连续。原始的「小于死区就置为最小值」在 10 px → 11 px 处让角速度从 0.011 跳到 0.05，是 4.5 倍阶跃。

连续化写法：死区内不动，死区外从「线性控制律在死区边缘取值」平滑升到下限：

python
def deadband_floor(w_raw, input_abs, deadband_in, ramp_in, min_w, max_w):
    """把不足 min_w 的微小指令连续抬到 min_w，消除阶跃。"""
    a = input_abs
    if a <= deadband_in:                   # 死区内不抬，防中心震荡
        return clamp(w_raw, -max_w, max_w)
    if abs(w_raw) >= min_w:                # 大误差走原控制律
        return clamp(w_raw, -max_w, max_w)
    w_edge = abs(w_raw) * (deadband_in / a)          # 死区边缘的 |w|
    t = clamp((a - deadband_in) / max(ramp_in, 1e-9), 0.0, 1.0)
    mag = w_edge + (min_w - w_edge) * t              # 分段线性过渡
    return clamp(math.copysign(mag, w_raw), -max_w, max_w)

五、执行层：当惯性单元坏了 ​

5.1 一次硬件故障改写架构 ​

设计上旋转/直行应该用滤波融合后的里程计（融合惯性单元，免疫打滑）。实测发现：

信号车以 0.317 rad/s 旋转时判定
轮式里程计航向-27.86°正常
融合里程计航向-0.06°被拖死
惯性单元角速度 z0.0013 rad/s无输出

融合配置本身没错，但它融合了一个「报告车没在转」的惯性单元，航向就被钉住。断电重启无效，是硬件故障。任何依赖融合里程计做旋转闭环的代码都会永不满足退出条件，曾导致目标 -15° 实转 -150° 的 10 倍超转。

只能退回纯轮式里程计，代价是 5 m 直行漂 0.1–0.4°，由末端标签伺服吸收。

5.2 旋转闭环：累加有符号增量 ​

remain = abs(deg) - abs(turned) 有两个致命问题：转错方向也会累积绝对值并「达标」；角度归一化把超过 180° 折回后，-150° 和 -210° 无法区分。正确写法是累加有符号增量，并加超转保护：

python
def rotate_odom(node, deg, p):
    if abs(deg) < 0.1:            # 最小动作阈值：与「到位判据」分离
        return
    prev = node.odom["yaw"]
    turned = 0.0
    deadline = time.time() + math.radians(abs(deg)) / p.angular + 8.0
    while time.time() < deadline:
        cur = node.odom["yaw"]
        turned += norm_deg(math.degrees(cur - prev))     # 有符号增量
        prev = cur
        remain = deg - turned
        if abs(remain) <= p.step_tol_deg:                # 到位判据可放宽到 2°
            break
        if abs(turned) > abs(deg) * 1.5 + 5.0:           # 超转保护
            break
        w = p.angular if abs(remain) > 3.0 else p.min_angular
        node.publish(0.0, math.copysign(w, remain))
        node.spin(0.05)
    node.stop()

最小动作阈值必须与到位判据分离。 到位判据后来放宽到 2°（里程计不可靠时避免反复旋转），但「要不要执行这条指令」的阈值必须保持很小（旋转 0.1°、直行 0.5 mm）。两者混用会出一个很隐蔽的 bug：横向修正前的回正指令因为偏差常只有 0.4–1.5°，被当成「无需旋转」直接跳过，车头没摆正就转 90°。现场当时的说法是「它没先纠正自己」。

5.3 停距与时间标定 ​

停距判据用里程计位移 hypot(Δx, Δy) ≥ 目标距离，末段 15 cm 降速减少过冲。短距离场景里里程计位移会失真（横移实测偏差 0.78x–5.97x），所以保留了一套时间标定模式：按时长开环，用现场标定的系数换算，默认关闭，只在里程计明显不可信时启用。

六、长距离方案的边界 ​

6.1 现场结论 ​

短距方案里三融合是有效的：掉头后由 TAG 层纠偏，修掉了纯里程计直行约 14° 的航向漂移；丢线 ≥2 s 自动降级直行，在遮线实验里真实触发并走完剩余距离。

长距离不同，18 m 巡线跑通过一次去程（检出率 95%，终点伺服收敛），回程同一根线不稳定：反方向行驶时饱和度下降（S 中位数 80 → 73，S ≥ 100 的像素 1792 → 597），丢线后容易追右侧反光误检（偏差 +246 px），航向转出几十度。这套巡线因此算不上可用的长距离方案：它依赖当次的光照和地面状态，换时间、换方向就退化，而现场保证不了这两点。

6.2 补丁解决到什么程度 ​

这些措施提高了可用率，但没有改变前提：线上必须一直有稳定可检出的像素。

6.3 长距离的两条备选 ​

  1. 沿线布 tag：每隔若干米放一个标签，作为周期性重定位点；每段把车伺服回该点的示教位姿，累积误差不跨段传递，段间用里程计或巡线走。代价是布点与维护、每个点都要示教，标签脏污、遮挡、逆光都会让这一段失效。
  2. 缩短行程：直行 + 原地掉头，两端靠标签伺服。目前采用这条：单程 3.5 m 量级，两端各有标签，中间不依赖巡线。

6.4 当前状态 ​

长距巡线暂停使用。重新启用前要先做一次 18 m 第一段的回归：死区补偿改过，转向行为已经和当初不同。目前实际在跑的是短距方案。
