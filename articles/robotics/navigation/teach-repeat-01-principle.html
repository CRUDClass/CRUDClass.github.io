示教-复现（一）：不标定相机也能做到 ±2cm 定点

机器人 ROS2

免标定的定点方案：用示教-复现抵消相机系统误差，实测 0.5m 处重复性 0.06mm，并给出角点精化、中值滤波与 seq 契约的源码实现

标签：
AprilTag 示教复现 视觉测量
发布于 2026年11月22日

前言 ​

这是一套两轮差速巡检车的定点方案：任务要求从起点沿地面红线走 18 m 到监测点，做完检测再原路返回，两端重复定位精度 ±2 cm / ±1°，且不拆车、不加标定板、不加额外传感器。实际落地时因为光照限制缩短了行程（原因见第三篇）。

一、任务与硬约束 ​

项实际情况对算法的约束
底盘两轮差速，轮速正解输出里程计只接受线速度与角速度，没有横移能力
相机车头单目彩色相机横向半视野约 ±35°，标签出画即失去全部外部基准
计算aarch64 + ROS2，OpenCV 4.5不能用新 API，算法要跑得动
场地18 m 地面红线，光照随时间变化，中远场有一片固定红区视觉必须能降级，不能一丢线就停
惯性单元陀螺 Z 轴硬件失效航向闭环不能用滤波融合结果，只能退回纯轮式里程计

路线是「去程与返程对称」的直角折线：

text
                      终点标签 id=0（200 mm，法向朝 -Y 迎向车头）
                                 ▲
                                 │ 第二段 ≈ 0.3–0.5 m
 起点 (0,0) ───── 第一段 = 18 m ─────▶ 拐点 ──左转 90°──▶ 监测点
    ▲                            │
    │                        返程：倒车第二段 → 左转 90°
    └────────── 第一段 ◀─────────┘
    起点标签 id=1（200 mm，法向朝 +X 迎向返程车头）

两个标签的法向都朝着到达时车头的方向。出发时车头朝 +X，起点标签在车尾，相机看不到它，所以去程不做出发对准，起始误差由终点标签的伺服吸收。

二、先放弃的三条路 ​

纯里程计。 轮式编码器正解，装上装后轮胎压缩、左右载荷不等，纵向系统欠走约 2.2%（5 m 走成 4.889 m，重复性 2 mm，可以标定），但横向漂移的符号会翻，标定消不掉，只能靠外部基准。里程计本身也看不见这类误差。

把巡线当定位。 巡线只给横向偏差，没有终点判据、不控航向，最小转弯半径 ≥0.26 m，拐不了直角。它在合适的光照下能带车走完 18 m，换个方向或光线变了就退化，也停不到指定位置。

开环定时脉冲。 按固定时长发速度：线位移步长 1.6 cm 已经等于容差本身；角度脉冲有上限，2° 的修正永远转不到；小修正低于底盘死区，车原地不动。三个问题叠在一起，收敛全靠运气。

最后的分工是：巡线负责长距离移动，标签负责最后 1 m 的位姿收敛，里程计负责距离判据和丢线兜底。三者各有盲区，盲区不重叠。

三、示教-复现：让系统误差自己抵消 ​

3.1 一次实测暴露了相机的真实模型 ​

用卷尺在 0.5 / 1 / 2 m 三个点量测距，拟合出的测量模型是：

text
measured = 0.9645 × true + 0.0172     （单位：米，RMS 残差 0.28 cm）

也就是说相机报的距离系统性偏小 3.5%，还带一个 1.7 cm 的常数偏移。根因在驱动：它把深度模组的内参填给了彩色流，两个物理独立的器件共用同一套 fx/fy/cx/cy，畸变系数还被强制清零。

正常做法是标定、修内参、补尺度。这里换了条路。

3.2 代数：同一个错犯两次 ​

示教时把车推到理想位置，记录相机读数 golden = (x, z, yaw)；复现时把车伺服到「读数等于 golden」：

text
s · true + b = s · true_g + b
        ⇒  true = true_g

只要测量映射 f(·) 在示教与复现两次是同一个确定性函数，无论它是线性的、带畸变的、还是尺度错的，等式两边同时被作用一次，误差完全抵消。内参误差、外参缺失、镜头畸变、标签尺寸偏差，全都属于「同一个错犯两次」。

于是这个方案不需要内参标定、不需要相机到车体的外参、不需要尺度补偿，精度只由测量的重复性决定。

3.3 这条结论的边界 ​

它消灭的是确定性偏差，不是噪声，也不是物理约束：

  • 示教与复现的车体朝向必须一致。相机系读数依赖相对位姿，起点设定点记录的是「返程到达时的朝向（车头朝 -X）」，不是出发朝向。
  • 标签尺寸改了必须重新示教。曾把终点标签从 124 mm 换成 200 mm 来扩大检出距离，尺寸一变，位姿估计的 x/z/yaw 全变，旧的 golden 直接作废。
  • 相机、分辨率、检测算法换任何一个，都要重做示教。等价性建立在「同一条测量链」上。

现场实测的重复性：0.5 m 处 z 的标准差 0.06 mm、yaw 0.02°。实际落盘的设定点（100 帧统计）也在这个量级：

设定点xzyawz 的 stdyaw 的 std
终点 id=0-2.14 cm75.65 cm-0.526°0.063 mm0.006°
起点 id=1+3.42 cm75.83 cm-0.407°0.026 mm0.015°

两处 x 都不是 0：手推示教时标签本来就不会落在画面正中。第二篇里的伺服事故就出在这个偏移上。

四、测量层：把抖动压到 0.1 mm 级 ​

检测器基于 OpenCV 的 aruco 模块跑 AprilTag 36h11，做了三件事。

角点精化选 CORNER_REFINE_APRILTAG。 同一段静止画面下三种模式的角点抖动：NONE 0.118 px、SUBPIX 0.226 px、APRILTAG 0.028 px。差 4 倍。0.1 px 的角点噪声在 0.75 m 处会放大成毫米级距离噪声，选型上不能忽略。

N 帧中值滤波。 每个 id 维护一个长度 5 的窗口，对 (x, y, z, yaw) 逐分量取中值。均值会被离群帧拖走（标签被遮挡半帧、反光过曝），中值不会：

python
class TagObs:
    """单个 id 的滤波状态：滑动窗口 + 单调 seq + 最新时间戳。"""

    def __init__(self, window=5):
        self.buf: deque = deque(maxlen=window)
        self.seq = 0
        self.stamp = 0.0

    def push(self, x, y, z, yaw):
        self.buf.append((x, y, z, yaw))
        self.seq += 1
        self.stamp = time.time()

    def median(self):
        if not self.buf:
            return None
        return np.median(np.asarray(self.buf), axis=0)   # x, y, z, yaw

单调递增的 seq。 这是给消费者的契约：seq 不变就说明是同一帧，不能算一次新样本。旧实现只看时间戳，15 fps 下同一帧可以被判定「连续 N 次达标」，收敛判据形同虚设。

位姿估计只做一次标定式转换，不做任何外参变换，这也是第三节能成立的前提：

python
rvec, tvec, _ = cv2.aruco.estimatePoseSingleMarkers([corner], tag_size, K, D)
t = np.asarray(tvec).reshape(3)          # 相机系：x 右、y 下、z 前
yaw, _, _ = yaw_pitch_roll_deg(rvec[0])  # 只取绕光轴的转角
obs[tid].push(float(t[0]), float(t[1]), float(t[2]), yaw)
med = obs[tid].median()                  # 发布中值，不发布原始帧
publish_pose(tid, med, seq=obs[tid].seq)

检测器只订阅图像、只发布位姿，不发布控制指令；示教页面复用同一个检测对象，所以页面看到的读数和伺服用的读数是同一条链。

五、与旧实现的四处缺陷对照 ​

#旧实现本实现
1横向误差靠原地旋转消除，只把标签转到光轴上，真实横向位置不变改走弧行，边走边转，同时收敛横向与航向
2从不读航向，姿态误差永远留着航向独立成一项，终态三轴同时判据
3开环定时脉冲，步长 ≈ 容差本身按余差比例算步长，闭环测量后再动
4收敛判据只看时间戳，同一帧可满足多次要求连续 N 个新 seq

第 4 条最容易被忽略：它不影响单步精度，但会让收敛判定出现误报。

六、小结 ​

示教-复现成立的前提是：测量链稳定，且示教与复现共用同一条链。满足这个前提，标定的成本和风险可以省掉；不满足，标定也救不了，因为决定精度的是重复性，不是绝对准确度。
