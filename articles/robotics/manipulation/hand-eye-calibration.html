一、问题定义 ​

已知一组对应点 (camera_xyz_i, robot_xyz_i)，求两者之间的变换 T。相机系的三维点由 PnP 从标定板求得，机器人系的坐标由机械臂位姿回读得到。两点都是“已知量”，中间那层变换是待求的未知量。

这是标准的手眼标定：解一个含噪声最小二乘问题。噪声来源有三类，全部要处理：

噪声源表现处理手段
角点检测误差亚像素级抖动ChArUco + 亚像素细化
板尺寸错误乘性尺度偏差尺子实测 + 交叉验证
人工采点错点局部大残差离群剔除

第三类可以事后剔除，第二类必须事前实测，本文第六节那个事故就出在这一类上。

二、标定板：为什么用 ChArUco ​

系统保留了棋盘格回退路径，但主力是 ChArUco（棋盘格 + ArUco 标记）。

2.1 两种板子的问题 ​

棋盘格ChArUco
角点精度亚像素，很好亚像素，很好
部分遮挡整体失效有多少标记认多少角点
姿态歧义转 90° 可能识别成别的布局ID 唯一，无歧义
3D 坐标需自己按物理尺寸生成板对象直接给出
检测速度快稍慢（要先找 marker）

棋盘格的两个死穴都在「部分遮挡」和「旋转歧义」上。现场标定时机械臂末端常常挡住板的一角，棋盘格直接整体检不出；而板子摆歪了 90° 更是常见的采点事故。

2.2 板子的构造与校验 ​

python
def aruco_dictionary(dictionary_name):
    name = dictionary_name.strip()
    if not name.startswith("DICT_"):
        name = f"DICT_{name}"
    dictionary_id = getattr(cv2.aruco, name, None)
    if dictionary_id is None:
        raise ValueError(f"Unsupported ArUco dictionary: {dictionary_name}")
    return cv2.aruco.Dictionary_get(dictionary_id)


def build_charuco_board(squares_x, squares_y, square_size, marker_size, dictionary_name):
    validate_charuco_config(squares_x, squares_y, square_size, marker_size)
    return cv2.aruco.CharucoBoard_create(
        int(squares_x), int(squares_y),
        float(square_size), float(marker_size),
        aruco_dictionary(dictionary_name),
    )


def validate_charuco_config(squares_x, squares_y, square_size, marker_size):
    if squares_x <= 2 or squares_y <= 2:
        raise ValueError("ChArUco square counts must both be greater than 2")
    if square_size <= 0.0:
        raise ValueError("ChArUco square size must be positive")
    if marker_size <= 0.0 or marker_size >= square_size:
        raise ValueError("ChArUco marker size must be positive and smaller than square size")

配置是 13×7 方格、DICT_4X4_50、方格 39 mm、marker 29.25 mm（40/30 比例）。

那个校验函数挡掉三种配置错误，每一种都会让后续计算彻底错误，而它自己不报错：

  • 方格数 ≤ 2：板画不出来，或者只能认到 1 个角点；
  • 方格尺寸 ≤ 0：PnP 会算出负尺度；
  • marker ≥ square：marker 会溢出到相邻格，检测到的 marker 角点根本不属于这个格子。

第三条尤其隐蔽：图能生成、marker 也能检出，但 interpolateCornersCharuco 的对应关系全错，最终只表现为「重投影 RMSE 很大但看不出原因」。在入口处挡掉，比在下游调试省十倍时间。

三、检测链路：四步 ​

3.1 先找 marker，再插值角点 ​

python
def detect_charuco_points(image, intr, squares_x, squares_y,
                          square_size, marker_size, dictionary_name, min_corners):
    board = build_charuco_board(squares_x, squares_y, square_size,
                                marker_size, dictionary_name)
    dictionary = aruco_dictionary(dictionary_name)
    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)

    # ① 检测所有 marker
    params = cv2.aruco.DetectorParameters_create()
    marker_corners, marker_ids, _ = cv2.aruco.detectMarkers(
        gray, dictionary, parameters=params)
    marker_count = 0 if marker_ids is None else int(len(marker_ids))
    if marker_ids is None or marker_count == 0:
        raise RuntimeError("Failed to detect ChArUco markers")

    camera_matrix = np.array(intr.k, dtype=np.float64).reshape(3, 3)
    dist_coeffs = np.array(intr.d, dtype=np.float64)

    # ② 由 marker 插值出棋盘格角点
    count, charuco_corners, charuco_ids = cv2.aruco.interpolateCornersCharuco(
        marker_corners, marker_ids, gray, board,
        camera_matrix, dist_coeffs)
    if charuco_ids is None or charuco_corners is None or int(count) < int(min_corners):
        raise RuntimeError(
            f"Detected only {int(count)} ChArUco corners, need at least {int(min_corners)}")

    # ③ 估板位姿
    rvec = np.zeros((3, 1), dtype=np.float64)
    tvec = np.zeros((3, 1), dtype=np.float64)
    ok, rvec, tvec = cv2.aruco.estimatePoseCharucoBoard(
        charuco_corners, charuco_ids, board,
        camera_matrix, dist_coeffs, rvec, tvec)
    if not ok:
        raise RuntimeError("estimatePoseCharucoBoard failed")

    # ④ 板位姿 -> 板上每个角点的相机系坐标
    object_points = np.asarray(board.chessboardCorners, dtype=np.float64)
    rotation, _ = cv2.Rodrigues(rvec)
    camera_points = (rotation @ object_points.T + tvec).T

    projected_all, _ = cv2.projectPoints(
        object_points, rvec, tvec, camera_matrix, dist_coeffs)
    corners_px = projected_all.reshape(-1, 2).astype(np.float32)

    # 重投影误差只在"实际检出"的那些角点上算
    ids = charuco_ids.reshape(-1).astype(np.int32)
    projected_detected, _ = cv2.projectPoints(
        object_points[ids], rvec, tvec, camera_matrix, dist_coeffs)
    reprojection_error = (projected_detected.reshape(-1, 2)
                          - charuco_corners.reshape(-1, 2).astype(np.float64))
    reprojection_rmse_px = float(
        np.sqrt(np.mean(np.sum(reprojection_error ** 2, axis=1)))
    )

    return (corners_px, camera_points.astype(np.float64),
            reprojection_rmse_px, int(count), marker_count)

四个要点：

① min_corners 是硬门槛（配置为 12）。少于这个数，PnP 会在平面内方向病态。3 个点就能解出唯一 PnP 解，但那个“唯一”是在无噪声假设下成立的；有噪声时，点太少会让解在法向方向剧烈抖动。

② interpolateCornersCharuco 要传内参和畸变系数。 它内部先用 marker 的已知 3D 坐标做一次粗略 PnP，再用这个位姿预测棋盘角点位置，最后在预测位置附近做亚像素细化。传错内参，插值点会落在错误的位置，而后续所有统计都会被污染。

③ estimatePoseCharucoBoard 的初值是全零。 OpenCV 内部会自动找初值（用平面假设），所以传零是安全的；但如果板子几乎正对相机、又有拒绝解的情况，可以传上一次的位姿作初值加速收敛。

④ 重投影误差只在「实际检出」的角点上算。 如果拿 projected_all（所有角点的预测位置）去和检出的角点比，长度都对不上，所以代码里显式用 object_points[ids] 对齐。这类“长度不匹配”的错误，在某些实现里会被 numpy 广播悄悄吃掉，产生一个看起来合理的错误数字。

3.2 重投影 RMSE 是体检指标 ​

python
reprojection_rmse_px = sqrt( mean( sum( (projected - detected)^2 ) ) )

判读标准：

RMSE含义处置
< 0.5 px优秀直接用于标定
0.5–1.0 px正常可用
1.0–2.0 px偏大板子太斜 / 角点模糊 / 畸变系数错
> 2.0 px不可用拒绝采点，重摆板

它是上游所有问题的汇总指标，也是唯一能在「还没触碰机械臂」之前就发现问题的机会。如果不看它直接采 20 个点，最后求出的矩阵精度被锁死在这个环节。

3.3 棋盘格回退路径的细节 ​

python
def find_corners(image, cols, rows):
    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
    pattern_size = (cols, rows)

    ok, corners = cv2.findChessboardCornersSB(gray, pattern_size, None)
    if ok:
        return corners.reshape(-1, 2).astype(np.float32)

    flags = cv2.CALIB_CB_ADAPTIVE_THRESH | cv2.CALIB_CB_NORMALIZE_IMAGE
    ok, corners = cv2.findChessboardCorners(gray, pattern_size, flags)
    if not ok or corners is None:
        raise RuntimeError("Failed to detect chessboard corners")

    criteria = (cv2.TERM_CRITERIA_EPS + cv2.TERM_CRITERIA_MAX_ITER, 30, 0.001)
    refined = cv2.cornerSubPix(gray, corners, (11, 11), (-1, -1), criteria)
    return refined.reshape(-1, 2).astype(np.float32)

先试 findChessboardCornersSB（sector-based，自带亚像素精度，对环境要求高但结果最好），失败再退到经典 + cornerSubPix 细化。

cornerSubPix 的 (11, 11) 是搜索窗口半径，不是越大越好：窗口大于方格间距时会跨到相邻格，把角点拉向错误的位置。经验值是窗口直径 ≤ 方格边长。

3.4 板位姿 → 角点三维坐标 ​

python
rotation, _ = cv2.Rodrigues(rvec)
camera_points = (rotation @ object_points.T + tvec).T
python
camera_points = (rotation @ object_points.T + tvec).T

推导：PnP 给出板在相机系的位姿 (R, t)，板坐标系下角点 P_i 的相机系坐标就是 R·P_i + t。

这一步把“图像上的点”变成了“相机系的三维点”，从此与深度图无关。精度只取决于 PnP 与板的物理尺寸，这也是第六节里反复强调「板尺寸实测」的原因。

另一个常见错误是把 (R @ object_points.T + tvec).T 与 object_points @ R.T + t 混用。两者在数学上等价（(R·P)ᵀ = Pᵀ·Rᵀ），但漏掉转置的后果是形状从 (N,3) 变成 (3,N) 或者广播错位。这种错误在小数据量下不会报错，只会让后面对应点的配对完全错乱，残差莫名其妙地大。

四、刚体求解：Kabsch 闭式解 ​

4.1 完整实现 ​

python
def rigid_transform(camera_pts, robot_pts):
    cam_centroid = camera_pts.mean(axis=0)
    rob_centroid = robot_pts.mean(axis=0)

    cam_centered = camera_pts - cam_centroid
    rob_centered = robot_pts - rob_centroid

    h = cam_centered.T @ rob_centered          # 3x3 协方差矩阵
    u, _, vt = np.linalg.svd(h)
    r = vt.T @ u.T
    if np.linalg.det(r) < 0:                   # 反射修正，见 4.3
        vt[-1, :] *= -1
        r = vt.T @ u.T

    t = rob_centroid - r @ cam_centroid
    pred = (r @ camera_pts.T).T + t
    rmse = float(np.sqrt(np.mean(np.sum((pred - robot_pts) ** 2, axis=1))))
    return r, t, rmse

4.2 推导 ​

目标函数：

min over (R, t):  sum_i || R * p_i + t - q_i ||^2
subject to:       R 是正交矩阵，det(R) = 1

第一步：消掉 t。 对 t 求偏导置零，得

t = q_bar - R * p_bar

代回目标函数，问题退化为只求 R：

min over R:  sum_i || R * p_i_c - q_i_c ||^2

展开（「_c」表示已中心化）：

sum ||R p||^2 - 2 * sum <R p, q> + sum ||q||^2

第一项因 R 正交等于 sum ||p||^2（常数），第三项也是常数。所以等价于最大化

sum_i <R * p_i_c, q_i_c> = trace(R * H),   H = sum_i p_i_c q_i_c^T

第二步：用 SVD 求上界。 令 H = U Σ Vᵀ，则

trace(R * H) = trace(R * U * Σ * V^T) = trace(V^T * R * U * Σ)

设 M = Vᵀ R U，它是正交矩阵，且 trace(M Σ) = sum_i M_ii σ_i ≤ sum_i σ_i（因为 M_ii ≤ 1）。等号成立当且仅当 M = I，即

R = V * U^T

这就是代码里的 vt.T @ u.T。

4.3 反射修正：不能省的一步 ​

SVD 给出的 V Uᵀ 可能是反射矩阵（行列式 −1）。它在数学上让残差更小，对应却是「镜像」，手性反了。

物理后果是机械臂往完全错误的方向走，症状也很典型：

大部分点都对，少数点误差巨大且方向诡异。

如果标定报告里出现「用了 20 个点，RMSE 5 mm，但最大误差 300 mm」，先查反射，不要查数据。

修法是把 V 的最后一列取反（对应最小奇异值方向），以最小代价换回合法旋转：

python
if np.linalg.det(r) < 0:
    vt[-1, :] *= -1      # 翻转 V 的最后一列
    r = vt.T @ u.T

为什么翻转最后一列代价最小？因为 H 的奇异值按降序排列，最后一列对应方差最小的方向，在那个方向上翻转，对拟合残差的影响最小。

还有一层：如果采样点的平面性很强（比如所有点都在同一个高度），第三个奇异值会非常小，反射与否在残差上几乎看不出差别，差的是 0.001 mm 级别，但结果差一个镜像。这种情况只能用物理常识验证：让机械臂动 +X，看相机图像里的点是往左还是往右。数学上这里给不出信息。

五、离群剔除：贪心而非 RANSAC ​

采样点是人工采的：操作员把末端对准角点，按回车。过程中必然有坏点，比如手抖、看错角点编号、机械臂还没停稳就读了位姿。

5.1 完整算法 ​

python
def solve_rigid_top(correspondences, min_used_points=None, outlier_threshold_m=None):
    min_used_points = int(getattr(cfg, "CALIBRATION_MIN_USED_POINTS", 6))
    outlier_threshold_m = float(getattr(cfg, "CALIBRATION_OUTLIER_THRESHOLD_M", 0.012))

    n = len(correspondences)
    if n < min_used_points:
        raise RuntimeError(f"至少需要 {min_used_points} 组点")

    camera_pts_all = np.array([c.camera_xyz_m for c in correspondences], dtype=np.float64)
    robot_pts_all  = np.array([c.robot_xyz_m  for c in correspondences], dtype=np.float64)
    used_indices = list(range(n))
    rejected_indices = []

    while True:
        sub_src = camera_pts_all[used_indices]
        sub_dst = robot_pts_all[used_indices]
        rotation, translation, rmse = rigid_transform(sub_src, sub_dst)
        pred = (rotation @ camera_pts_all[used_indices].T).T + translation
        errors = np.linalg.norm(pred - robot_pts_all[used_indices], axis=1)
        # 已到下限，或最大残差已进阈值 -> 停止
        if len(used_indices) <= min_used_points or float(errors.max()) <= outlier_threshold_m:
            break
        reject_local = int(np.argmax(errors))
        rejected_indices.append(used_indices.pop(reject_local))

    ...

算法就是三步循环：拟合 → 找最大残差点 → 扔掉 → 重拟合，直到「最大残差 ≤ 12 mm」或「只剩 6 个点」。

5.2 为什么不用 RANSAC ​

这里 N 很小（9–25 个点），而坏点比例可能高达 30%。

RANSAC 靠随机抽子集找全内点解。设内点比例 p = 0.7，每次抽 k = 6 个点全好的概率是

p^k = 0.7^6 ≈ 0.118

要达到 95% 置信找到一次全内点子集，需要

log(1 - 0.95) / log(1 - 0.118) ≈ 24 次迭代

每次迭代都要做一次 SVD 加一次全量残差计算。而贪心：20 个点最多 14 次 SVD，每次只用当前子集。成本差一个数量级，且在坏点稀疏（不聚集）时贪心的结果通常更好。

5.3 贪心的代价与缓解 ​

贪心会吃掉边缘的好点：两个点残差接近时，它可能先扔错那个，因为每次只扔「当前最大」，扔掉的点不再回来。

缓解的办法是把诊断信息全部记下来，让人来判断，而不是去改算法：

python
diagnostics = {
    "total_count": n,
    "used_indices": used_indices,
    "rejected_indices": rejected_indices,
    "used_count": len(used_indices),
    "rejected_count": len(rejected_indices),
    "rmse_used_m": float(rmse),
    "rmse_all_m": float(np.sqrt(np.mean(errors_all * errors_all))),
    "max_error_all_m": float(errors_all.max()),
    "camera_span_m": camera_span.tolist(),
    "robot_span_m": robot_span.tolist(),
    "board_pose_ids": board_pose_ids,
    "board_pose_count": len(board_pose_ids),

    "warnings": warnings,
    "point_errors": point_errors,

5.4 诊断字段的读法 ​

这套字段把「标定好不好」从主观判断变成了可查的数据：

字段判读
used_count / total_count剔除率。超过 40% 说明数据源有系统性问题，不是点的问题
rmse_used_m拟合残差，越小越好
rmse_all_m全量残差。与 rmse_used 差得越远，说明剔除掩盖的问题越严重
max_error_all_m单点最坏情况，决定敢不敢在该位置使用
board_pose_count板位姿覆盖数。少于 3 会告警
camera_span_m / robot_span_m点集主轴跨度，可观测性代理
point_errors逐点残差向量，「哪一点坏、在哪个方向坏」一眼可见

rmse_used 与 rmse_all 的对照是最容易漏看的一条。 只看 rmse_used 会得到“标定很准”的错觉；两者一起看才知道「准」是靠扔掉一半点换来的。

5.5 几何覆盖：比 RMSE 更早发现问题 ​

python
camera_span = np.ptp(camera_pts_all, axis=0)
robot_span  = np.ptp(robot_pts_all,  axis=0)

warnings = []
if not arm_sides:
    warnings.append("采样点没有机械臂侧标记")
elif len(arm_sides) > 1:
    warnings.append(f"采样点混用了多个机械臂: {arm_sides}，建议左/右分开求解")
if len(board_pose_ids) < getattr(cfg, "CALIBRATION_RECOMMENDED_BOARD_POSES", 3):
    warnings.append(f"棋盘姿态只有 {len(board_pose_ids)} 个，建议至少覆盖 3 个不同位置/倾角")
if float(robot_span[2]) < 0.04:
    warnings.append(f"机器人 Z 覆盖范围只有 {robot_span[2]:.3f}m，建议增加高度变化")
if rejected_indices:
    warnings.append(f"已自动剔除 {len(rejected_indices)} 个残差较大的点")

只看 RMSE 会被骗。如果你把所有点都采在同一个平面上，最小二乘会给出一个 RMSE 很小、但在垂直该平面方向上完全错误的解，因为那个方向没有约束。

用 np.ptp（peak-to-peak，各轴最大值减最小值）作为可观测性代理，比 RMSE 更早发现问题。三条告警对应的都是“约束不足”：

  • 板位姿少于 3 个 → 旋转在板法向病态；
  • Z 跨度小于 4 cm → 垂直方向（通常是深度轴）没有约束；
  • 混用左右臂 → 两组不同的外参被强行拟合成一个。

六、仿射：把乘性误差一起拟合掉 ​

6.1 实现 ​

python
def fit_affine(camera, robot):
    """最小二乘求解 3x4 仿射矩阵。返回 dict 含矩阵与诊断字段。"""
    design = np.column_stack([camera, np.ones(len(camera), dtype=np.float64)])   # N x 4
    m, residuals, rank, singular_values = np.linalg.lstsq(design, robot, rcond=None)
    affine_3x4 = m.T                                                            # 4x3 -> 3x4

    pred = design @ m
    resid = pred - robot
    errors = np.linalg.norm(resid, axis=1)

    transform = np.eye(4, dtype=np.float64)
    transform[:3, :] = affine_3x4

    return {
        "affine_3x4": affine_3x4,
        "transform": transform,
        "rank": int(rank),
        "singular_values": singular_values,
        "residuals_lstsq": np.atleast_1d(residuals),
        "resid_xyz": resid,
        "errors": errors,
        "rmse_m": float(np.sqrt(np.mean(errors ** 2))),
        "mean_error_m": float(np.mean(errors)),
        "max_error_m": float(np.max(errors)),
    }

模型：q = A · p + b，A 是 3×3、b 是 3×1，共 12 个参数。设计矩阵是 [p | 1]（N×4），一次 lstsq 解出 M（4×3），再转置成 A（3×4）。

6.2 那 6 个多出来的自由度吸收了什么 ​

把 A 做极分解 A = R · S（S 对称正定），S 就是各向异性的尺度/剪切。

真实误差数学形式刚体能吸收仿射能吸收
标定板方格尺寸标注偏小各向同性缩放 s·I否是
深度图远端精度衰减沿深度轴缩放否是
相机安装轻微倾斜小角度剪切否是
相机坐标系原点偏移平移 b是是

所以仿射是刚体的严格超集，只要点数够且不共面，仿射的残差一定不大于刚体。工程上默认用仿射（CLICK_MOVE_USE_AFFINE = True）就是这个理由。

6.3 rank 是必检项 ​

np.linalg.lstsq 返回的 rank 小于 4，说明设计矩阵列线性相关：

  • 最常见原因：所有采样点共面。此时 [x, y, z, 1] 里有一列可由其他列线性组合，仿射解不唯一——求解器会给出一个“合法”但在该平面外完全失控的解。
  • 另一个原因：某一轴几乎没有变化（比如所有点 X 都是同一个值），对应列接近常数列。

代码把 rank 和 singular_values 都写进了输出：

python
"diagnostics": {
    "rank": fit["rank"],
    "singular_values": [float(v) for v in fit["singular_values"].tolist()],
    "residuals_lstsq": [...],
    "board_pose_ids": board_pose_ids,
    "board_pose_count": len(board_pose_ids),
    "camera_span_m": (camera.max(axis=0) - camera.min(axis=0)).tolist(),
    "robot_span_m":  (robot.max(axis=0)  - robot.min(axis=0)).tolist(),
    "point_errors": point_errors,
}

而大多数人只看 RMSE。这是仿射拟合里最容易犯的错：RMSE 很好，rank 却只有 3，说明模型在某个方向上完全没有被约束，一旦超出采样区域就会崩。

6.4 幂等性：不许二次缩放 ​

重缩放（按真实方格尺寸修正 camera_xyz）是一个破坏性操作。做两次会累积误差，所以代码里显式拦截：

python
existing_factor = data.get("camera_xyz_rescale_factor")
if rescale_from is not None:
    if existing_factor is not None:
        raise ValueError(
            f"points 文件已缩放过 (factor={existing_factor}, "
            f"{existing_old_square} -> {existing_new_square})，"
            f"再次缩放会累积误差。请先恢复 points 文件，或省略 rescale_from。")

并且在文件里留下元数据，让下一次运行知道「已经缩放过」：

python
item["charuco_square_size_m"] = rescale_info["new_square"]
item["charuco_marker_size_m"] = rescale_info["new_marker"]
item["camera_xyz_rescaled_from_square_size_m"] = rescale_info["old_square"]
item["camera_xyz_rescale_factor"] = rescale_info["scale"]

破坏性操作最好自带“已执行”标记。这条规则在标定、迁移、格式转换里都适用，靠人记住“上次跑过了”不可靠。

七、实战：一次被加性补偿掩盖的乘性尺度事故 ​

这是整条链路里最有教学价值的案例。

7.1 症状 ​

  • 某一侧机械臂点击移动 X 轴偏差大；
  • 操作员在补偿文件里加了 -0.06 m 的 X 补偿硬压下去；
  • 标定矩阵诊断：23 个点只用了 6 个（剔除 17 个），rmse_all 30 mm，max_error_all 60 mm，71 个角点判据只有 47 个通过。

注意第二行：补偿量 −6 cm 本身就是个红旗。正常的外参残余在毫米级，需要 6 cm 的补偿，说明有系统性问题。

7.2 四步诊断法 ​

第一步看矩阵健康度，读 diagnostics。剔除率 74% 且 rmse_all 远大于 rmse_used，这是拟合带系统性偏差的典型指纹，不是采样噪声。噪声的表现是「RMSE 中等，剔除率低，残差随机分布」。

第二步：尺度交叉验证（关键）。 对同一个对角跨度，比较「相机侧距离」和「机械臂侧距离」：

s = ||dq|| / ||dp||
  • ||dp||：相机侧，由 PnP 按配置的方格尺寸算出的角点间距；
  • ||dq||：机械臂侧，操作员真实触碰两点的距离。

本次：相机侧按 6 格 × 39 mm = 234 mm，机械臂侧实测 270 mm，

s = 270 / 234 ≈ 1.141

比值不等于 1 就是结论：真实方格比配置值大 14%，反推真实边长约 45 mm。

这个方法只需要两个点，不用重做标定，从现有数据里就能算出来。

第三步：实测屏幕方格。 拿尺子量显示器上的真实方格边长。确认它 ≠ 配置里的 39 mm。

第四步：查补偿是否在掩盖。 command_compensation 文件的 offset_m 若大于 2–3 cm，多半在掩盖矩阵尺度误差，而不是真正的补偿。

7.3 根因 ​

标定板生成器的全屏样式用了：

css
#board-view:fullscreen { height: 100vh; max-width: 100vw }

把按物理尺寸生成的 PNG（2214 px 宽）拉伸填满 2560 px 的屏宽，放大 1.156 倍。39 mm 的方格物理上变成约 45 mm。

后果链条：

PNG 被拉伸 1.156x
  -> 屏幕上真实方格 45 mm
  -> PnP 仍按配置 39 mm 计算
  -> 相机侧点云尺度偏小到 0.877x (= 1/1.141)
  -> 刚体拟合大批剔点（尺度对不上）
  -> 运行时套到真实深度点上，偏约 15%

7.4 为什么加性补偿救不了 ​

设真实映射为

q = s * R * p + t,   s ≈ 1.141

而模型假设 s = 1，则残差为

residual = q - (R' * p + t') ≈ (s - 1) * R * p

残差与位置成正比，加性补偿只能改 t，改不了 s：

  • 在某个 6 格跨度（约 270 mm）上把补偿调到 -0.06 m，那个跨度是对的；
  • 换成 3 格跨度（135 mm），需要 −0.03 m；补偿还是 −0.06 m，过补一倍；
  • 换成 9 格，需要 −0.09 m，补偿不足。

操作员当时做的事，本质上是拿加法去补乘法。补偿量会大到 6 cm，就是因为它在掩盖一个 14% 的乘性误差。

7.5 修复与结果 ​

修复四步：

  1. 把 camera_xyz 按 真实方格/配置方格（≈1.141）整体缩放，等价于用真实尺寸重跑 PnP；
  2. 重拟合刚体 + 仿射；
  3. 清零 command_compensation 的 offset_m；
  4. 把生成器全屏样式改成 width/height: auto 不再拉伸。
指标修复前修复后
仿射 RMSE8.5 mm5.9 mm
最大残差16.8 mm10.9 mm
X 轴补偿−0.06 m0
剔除点数17 / 23大幅下降

注意，修复后的 RMSE 仍不是 0，因为还有无法消除的随机误差（深度量化、角点抖动、机械臂重复定位）。标定的目标不是把 RMSE 压到 0，而是把系统性误差清干净、只留下随机误差：随机误差会互相抵消，系统性误差不会。

7.6 三条可迁移的教训 ​

① 尺度先验必须实测，不能来自生成参数。pxPerMm、DPI 校正、打印机分辨率标注——这些都防不住全屏拉伸，因为拉伸量 = 屏宽/板宽，与 DPI 无关。所有“制造出来的物理量”在使用前都要实测一次。物理世界里没有“应该等于”。

② 数据驱动的尺度估计会被坏点拉偏。 这次拓扑上同一个 6 格跨度，一个姿态测出 270 mm、另一个测出 223 mm。用最小残差反解出的 k = 1.09 是错的；物理实测的 1.141 才对。坏触点要靠刚性拟合的离群剔除来识别，不能让它参与尺度估计。

③ 两侧设备共用同一参考却一好一坏时，先怀疑标定环境。 两侧共用同一台相机却只有一侧不准，说明相机没问题，差异在板、屏、采点流程。先查环境，不要拆硬件。

八、小结 ​

标定这一篇的六条：

  1. 「部分遮挡」和「旋转歧义」是选择 ChArUco 的唯一理由，其余特性棋盘格也能满足；
  2. 重投影 RMSE 是唯一的采点前体检，超过 2 px 不要继续；
  3. Kabsch 的反射修正不能省，症状是「少数点误差巨大」；
  4. 贪心剔除在 N 小、坏点率高时优于 RANSAC，代价是可能吃掉边缘好点，用诊断字段兜住；
  5. 仿射 rank 是必检项，RMSE 好看但 rank < 4 意味着过拟合；
  6. 乘性误差只能用乘性手段修，加性补偿只能掩盖一个位置，换一个就露馅。
