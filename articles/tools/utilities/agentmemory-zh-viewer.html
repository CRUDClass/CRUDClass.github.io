首页开发工具把 agentmemory 查看器改成中文：一段注入脚本，不 fork 不改源码

把 agentmemory 查看器改成中文：一段注入脚本，不 fork 不改源码

工具 agentmemory

不 fork 源码、不等上游 i18n，用一段运行期注入的脚本把 agentmemory 查看器翻成中文：复用 CSP nonce 占位符、三级词表匹配、DOM 增量翻译，升级后一条命令复原。

标签：
agentmemory 中文化 i18n CSP DOM
发布于 2026年11月22日

起因 ​

agentmemory 是我本机长期在跑的“记忆服务”，agent 干过的活、定过的决策、踩过的坑都存在里面，配了个 Web 查看器在 http://127.0.0.1:3111/agentmemory/viewer。

界面全是英文。倒不是看不懂，麻烦的是它自造了一批术语：Crystal、Consolidation、Lesson、Semantic facts……英文读着顺，中文脑子里还得现场翻译一次，而且每次都翻得不一样——同一页里 Memory 一会儿想成“记忆”一会儿想成“内存”。

所以决定中文化。要求只有三条：能用、能跟着升级走、出问题能一秒回退。

一、先看清要改的是什么 ​

动手前先摸清三件事，它们决定了方案的上限：

  1. 查看器是单文件。dist/viewer/index.html 530 KB，CSS 和 JS 全部内联，目录里除了一个 favicon 什么都没有。没有 locales 目录，没有 i18n 取词点；npm 包也只发布 dist，拿不到前端构建源码。
  2. 内容是动态渲染的。页面文本由接口和 SSE 推流生成，直接改 HTML 只能覆盖骨架（标题、导航壳子），列表、徽章、空状态全是运行期长出来的。
  3. CSP 非常严。响应头是 script-src 'nonce-…'; script-src-attr 'none'; style-src 'unsafe-inline'：外链脚本不行，内联 onclick 不行，内联 script 标签必须带 nonce。

第 3 条最麻烦，我差点卡在这里。

二、三条没走的路 ​

路线做法为什么不选
改包内源文件直接替换 index.html 里的英文升级即覆盖；530 KB 里大半是 JS 字符串和模板片段，静态替换只治骨架，动态文案照样英文
fork 重建拿到前端源码，接入 i18n 框架包只发 dist，源码拿不到；就算拿到也等于与上游永久分叉，上游一改版就得重新合
运行期注入在 HTML 末尾注入一段脚本，运行后改写 DOM需要解决 CSP；但一次投入、升级可复用、随时可撤

选了第三条。说白了就是给别人的页面打补丁，只不过这个页面在我自己机器的 npm 包里。

三、注入：关键在“借”一个 nonce ​

CSP 要求内联脚本带 nonce，而 nonce 每次请求随机生成，写死没用。解法是在翻查看器自己的 HTML 时找到的：

html
<script nonce="__AGENTMEMORY_VIEWER_NONCE__">

模板里写的是占位符，服务端下发时替换成真 nonce（实测响应头里的 nonce 和响应体里的完全一致）。我只要在自己的注入块里也写这个占位符，就天然合法，不用关心它换成了什么。

注入器逻辑很短，只做两件事：重复执行不叠加，出问题能撤。

js
const BEGIN = '<!-- zh-viewer:begin -->'
const END = '<!-- zh-viewer:end -->'
const NONCE = '__AGENTMEMORY_VIEWER_NONCE__'

let html = readFileSync(viewer, 'utf8')
// 1. 先剥掉旧块，保证重复执行不会叠加
html = html.replace(new RegExp('\\n?' + BEGIN + '[\\s\\S]*?' + END + '\\n?', 'g'), '\n')

// 2. 首次注入前备份原始英文版
if (!existsSync(bak)) copyFileSync(viewer, bak)

// 3. 插到 </body> 之前
const block = BEGIN + '\\n<script nonce="' + NONCE + '">\\n' + overlay + '\\n</script>\\n' + END
html = html.replace('</body>', block + '\\n</body>')
writeFileSync(viewer, html)

几处防御细节都是踩坑之后补的：

  • overlay 里如果出现收尾的 script 结束标签，直接报错退出，绝不写入（否则整页脚本被截断）。
  • 模板里没有 </body> 就拒绝写入。
  • 检测到“未被注入的新模板”时会顺手刷新备份，否则升级后再 --restore 会还原成上一个旧版本，比不还原更糟。

四、翻译：三级匹配，宁窄不宽 ​

改的范围是界面外壳，不是页面上所有英文。匹配做成三级，命中就返回：

js
function translate(value) {
  const t = value.trim()
  if (!t) return null
  if (MAP[t]) return MAP[t]                        // 1. 精确词表（约 400 条）
  for (const [p, r] of PREFIX)                     // 2. 前缀，如 Showing → 显示
    if (t.startsWith(p)) return r + t.slice(p.length)
  for (const [re, rep] of RULES) {                 // 3. 正则，处理带数字的句式
    const m = re.exec(t)
    if (m) return typeof rep === 'function' ? rep(m) : rep.replace(/\$(\d)/g, (_, d) => m[+d] || '')
  }
  return null
}

精确匹配放在最前，是因为英文界面里长度相近的词太多：Obs / observations / Observation 出现在不同位置，用模糊匹配必然串味。精确词表加整串比较最稳，代价是新词要一条条加。

三级规则里最有用的是正则。页面很多文案是拆成几段拼出来的：

js
[/^Showing ([\d,]+) of ([\d,]+) latest memories$/, '显示最新 $1 / $2 条记忆']
[/^(\d+)h ago(.*)$/, '$1 小时前$2']
[/^(\d+) sessions?$/, '$1 个会话']

DOM 层用 TreeWalker 扫文本节点，只改与整串匹配的部分（保留前后空白，避免把 · 分隔符粘掉）：

js
const w = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT, null)
while (w.nextNode()) textNode(w.currentNode)

属性也要处理，三类：placeholder / title / aria-label。script-src-attr 'none' 只禁内联事件属性，setAttribute 不受影响。

增量靠 MutationObserver（childList + subtree + characterData），60 ms 去抖后重跑一轮。查看器是 SSE 驱动的，不监听的话切个标签页就变回英文。

还有三处外壳文字要单独处理：

js
document.documentElement.lang = 'zh-CN'   // 模板里写死 lang="en"
document.title = 'agentmemory 查看器'      // title 是静态英文
// 徽章补一条 nowrap：中文比英文短，但行高更松，不禁换行会撑成两行
.badge, [class*=badge], .tag, .chip { white-space: nowrap; letter-spacing: 0 }

五、术语表 ​

同一个英文只给一个译法，新增词条先查表。节选：

英文中文备注
Memory / Memories记忆不译“内存”；“内存占用”另有其词
Observation观察不译“观测”
Lesson经验是“从纠正中学到的规则”，不是“教训”
Crystal / Crystals结晶已完成 action 沉淀出的成果
Consolidation整合后台把大量观察压成更持久记录的任务
Profile画像
Replay回放
Session会话

保持英文不译：agentmemory、SSE、LLM、MCP、JSON、bash、curl、ID、worker，以及函数名、参数、路径、命令。翻这些不是本地化，是给读者添麻烦。

六、哪些我故意没译 ​

中文化最容易犯的错是“看到英文就想翻”。这里划了两条线，都不碰：

  • 长说明文案：帮助段落、每页“这是什么 / 为什么是空的”整段解释。体量大、随版本改动剧烈，维护成本远超收益，留着英文反而好读。
  • 数据内容：LLM 生成的摘要、观察正文、经验正文，以及代码路径和命令。这些是用户数据，翻了会污染检索关键词，复制出来也不能用。

再加上跳过 code / pre / svg / 可编辑元素，JSON 块和代码片段始终保持原样。

最终形态是中文的壳加原文的内容。这不算完整本地化，但对开发者工具来说够用。

七、升级之后怎么办 ​

bash
~/.agentmemory/zh-viewer.patch.sh             # 注入 / 刷新（幂等，升级后跑这一条）
~/.agentmemory/zh-viewer.patch.sh --status    # 看 viewer 路径、备份、是否已注入
~/.agentmemory/zh-viewer.patch.sh --revert    # 只摘掉注入块，秒回英文
~/.agentmemory/zh-viewer.patch.sh --restore   # 用备份整体还原

npm 升级覆盖 dist/viewer/index.html 之后，中文就没了，重跑第一条命令即可。整个补丁都住在 ~/.agentmemory/zh-viewer/（两个文件，约 30 KB），不在包里，升级不会碰它。

回滚分四种情况：改错词表就重跑；想要英文就 --revert；文件改坏就 --restore；彻底不要就还原后删目录。

八、踩过的坑 ​

  1. CSP nonce：第一版直接插内联脚本，控制台一句 Refused to execute inline script，页面毫无反应。找 nonce 占位符花了最久，解决只用了一行。
  2. 半句拼接：Showing 12 of 3,204 latest memories 在 DOM 里是三段文本节点，逐节点翻译出来是“显示 12 的 3,204 最新记忆”。只能按整句写正则，绝不能拆词。
  3. 短词误伤：往词表里塞 chat、plan 这种通用词，会把数据里的英文也一起翻掉。规则改成：≤4 字符的短词只允许出现在带上下文的精确词条里，不进前缀和正则。
  4. 徽章换行：中文短，但行高松，badge 不禁换行会折成两行把表格撑歪。补一条 white-space: nowrap 解决。
  5. 用覆盖率骗自己：写了个脚本统计“源码里像界面文案的字符串有多少被翻译了”，结果是 22.2%，看着像失败。其实分母里大半是长帮助段落和前端模板片段（"Showing " 这种半句），本来就属于“故意不译”。这个数字衡量的是词表对源码字面量的覆盖，不是界面残留英文率。验收只能逐页看。

九、最后的结果 ​

项数值
注入脚本27 KB（精确词条 407 + 前缀 17 + 正则 49）
注入器3.5 KB
查看器体积530 KB → 558 KB（+5%）
界面外壳中文（导航、表头、按钮、状态、空状态、tooltip、placeholder）
数据与代码保持原文
升级成本一条命令

做完回头看，翻译本身花的时间不多。难的是定边界：哪些该译、哪些不该译、为了以后能维护要放弃什么。这三件事想清楚，代码量其实很小。

如果你也在用 agentmemory，这套补丁可以直接照搬；换个单文件 Web 工具也一样：找注入点、解决 CSP、写窄词表、留好备份。
