用 Docker Compose 部署私有镜像仓库

Docker

用 Docker Compose 部署 registry:3 私有镜像仓库，覆盖 TLS、htpasswd 认证、S3 后端、垃圾回收、客户端信任与 CI 推送

标签：
Docker Compose Registry 镜像仓库 TLS S3
发布于 2026年11月22日

前言 ​

官方的 Distribution Registry（镜像名 registry）只做一件事：按 OCI Distribution 规范存取镜像。它没有 Web 界面、漏洞扫描和多租户，好处是部署简单、资源占用低，数据完全自持。

适合的场景：内网构建产物存放、离线环境分发、给 CI 提供稳定的镜像地址。需要审计、扫描、细粒度权限时，应该选 Harbor 这类上层产品，而不是在 registry 上硬加。

当前主版本是 3.x，配置路径也从 2.x 的 /etc/docker/registry/config.yml 改成了 /etc/distribution/config.yml。

目录结构 ​

text
registry/
├── compose.yaml
├── .env
├── config.yml
├── auth/
│   └── htpasswd
└── certs/
    ├── registry.crt
    └── registry.key

.env 只放对象存储的访问密钥，auth/ 和 certs/ 的权限要收紧：

bash
chmod 600 .env auth/htpasswd certs/registry.key

compose.yaml ​

yaml
name: registry

services:
  registry:
    image: registry:3.1.2
    restart: unless-stopped
    environment:
      REGISTRY_STORAGE_S3_ACCESSKEY: ${REGISTRY_S3_ACCESS_KEY:?set in .env}
      REGISTRY_STORAGE_S3_SECRETKEY: ${REGISTRY_S3_SECRET_KEY:?set in .env}
      OTEL_TRACES_EXPORTER: none
    volumes:
      - ./config.yml:/etc/distribution/config.yml:ro
      - ./certs:/certs:ro
      - ./auth:/auth:ro
    ports:
      - "5000:5000"
    logging:
      driver: json-file
      options:
        max-size: "20m"
        max-file: "5"

registry 的配置支持用环境变量覆盖，命名规则是把配置层级用下划线连接、全大写：storage.s3.accesskey 对应 REGISTRY_STORAGE_S3_ACCESSKEY。这样密钥不用写进 config.yml。

OTEL_TRACES_EXPORTER: none 用来关掉 3.x 默认开启的链路导出。默认会尝试把 trace 发到 localhost:4318，没有 collector 时日志里会持续报连接失败。

config.yml ​

yaml
version: 0.1

log:
  level: info

storage:
  delete:
    enabled: true
  redirect:
    disable: true
  s3:
    region: us-east-1
    regionendpoint: https://s3.example.com
    bucket: registry
    forcepathstyle: true
    secure: true
    v4auth: true
    chunksize: 5242880
  maintenance:
    uploadpurging:
      enabled: true
      age: 168h
      interval: 24h

http:
  addr: :5000
  headers:
    X-Content-Type-Options: [nosniff]
  tls:
    certificate: /certs/registry.crt
    key: /certs/registry.key

auth:
  htpasswd:
    realm: registry
    path: /auth/htpasswd

health:
  storagedriver:
    enabled: true
    interval: 10s
    threshold: 3

配置项的作用：

配置作用
storage.delete.enabled允许通过 API 删除 manifest 和 tag，是垃圾回收的前提
storage.redirect.disable不让 registry 把客户端重定向到对象存储的内部地址
storage.s3.forcepathstyle自建对象存储通常只支持 path-style 访问
storage.s3.secure对象存储用 HTTPS 时设 true，内网 HTTP 设 false
storage.maintenance.uploadpurging清理中断的分片上传，避免占满桶
http.tls由 registry 自己终止 TLS；交给反向代理时删掉这一段
auth.htpasswdBasic 认证的用户文件
health.storagedriver定期检查存储后端可用性，状态反映在 /debug/health

只用本地磁盘时，把 storage.s3 换成：

yaml
storage:
  filesystem:
    rootdirectory: /var/lib/registry

并在 compose 里挂一个卷：服务下加 - registry-data:/var/lib/registry，顶层声明 registry-data。S3 后端的好处是镜像数据不占本地盘，扩容和备份都交给对象存储；代价是每次拉取都要走网络，延迟比本地盘高。

创建账号 ​

用 httpd 镜像里的 htpasswd 生成 bcrypt 哈希：

bash
mkdir -p auth
docker run --rm -it -v "$PWD/auth:/auth" httpd:2.4-alpine \
  htpasswd -B /auth/htpasswd deploy

交互式输入密码，密码不会留在 shell 历史里。追加用户重复执行同一条命令即可。-B 指定 bcrypt，registry 不支持明文和弱的 crypt 格式。

证书 ​

内网可以用自签证书，关键是带上 SAN，否则 Docker 客户端会报 x509: certificate relies on legacy Common Name field：

bash
mkdir -p certs
openssl req -x509 -nodes -newkey rsa:4096 -days 825 \
  -keyout certs/registry.key \
  -out certs/registry.crt \
  -subj "/CN=registry.example.com" \
  -addext "subjectAltName=DNS:registry.example.com"

客户端信任这个证书：

bash
sudo mkdir -p /etc/docker/certs.d/registry.example.com:5000
sudo cp certs/registry.crt /etc/docker/certs.d/registry.example.com:5000/ca.crt
sudo systemctl restart docker

目录名必须和访问地址完全一致（域名加端口）。用公网域名时更推荐让 Caddy、Nginx 或 registry 内置的 ACME 申请证书，而不是自签。

启动与推送 ​

bash
docker compose up -d
docker compose logs -f registry
docker login registry.example.com:5000

登录成功后做一次完整往返：

bash
docker pull alpine:3.22
docker tag alpine:3.22 registry.example.com:5000/demo/alpine:3.22
docker push registry.example.com:5000/demo/alpine:3.22

docker rmi registry.example.com:5000/demo/alpine:3.22
docker pull registry.example.com:5000/demo/alpine:3.22

查看仓库内容：

bash
curl -u deploy https://registry.example.com:5000/v2/_catalog
curl -u deploy https://registry.example.com:5000/v2/demo/alpine/tags/list

curl 会提示输入密码。部分部署会关闭 catalog 接口，这时只能按已知仓库名查询 tag。

垃圾回收 ​

删除 tag 只是删掉引用，blob 仍然占空间，需要显式跑垃圾回收。回收期间不能有推送，否则可能删掉正在上传的层：

bash
docker compose stop registry

# 先 dry-run 看会删什么
docker compose run --rm --entrypoint /bin/registry registry \
  garbage-collect --dry-run /etc/distribution/config.yml

# 确认后真正执行
docker compose run --rm --entrypoint /bin/registry registry \
  garbage-collect --delete-untagged /etc/distribution/config.yml

docker compose start registry

--delete-untagged 会顺带删除没有被任何 tag 引用的 manifest。没有这个参数时，只清理已经不可达的 blob。

被多个 tag 共享的层不会被删，这是内容寻址存储的正常行为，不用担心“删了一个 tag 把公共基础层删掉”。

反向代理 ​

把 TLS 交给 Nginx 时，registry 只监听 HTTP，代理需要：

nginx
server {
    listen 443 ssl;
    server_name registry.example.com;

    ssl_certificate     /etc/nginx/certs/registry.crt;
    ssl_certificate_key /etc/nginx/certs/registry.key;

    client_max_body_size 0;

    location / {
        proxy_pass http://registry:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

client_max_body_size 0 必须加，否则大镜像推送会得到 413。X-Forwarded-Proto 用来让 registry 生成正确的重定向地址。Nginx 和 registry 在同一个 Compose 网络时，proxy_pass 写服务名；Nginx 装在宿主机上时，改成 http://127.0.0.1:5000。

CI 推送 ​

GitLab CI：

yaml
build:
  script:
    - echo "$CI_REGISTRY_PASSWORD" | docker login -u "$CI_REGISTRY_USER" --password-stdin "$CI_REGISTRY"
    - docker build -t "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA" .
    - docker push "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA"

GitHub Actions：

yaml
      - uses: docker/login-action@v3
        with:
          registry: registry.example.com:5000
          username: ${{ secrets.REGISTRY_USERNAME }}
          password: ${{ secrets.REGISTRY_PASSWORD }}

CI runner 需要信任自签证书，把 CA 放到 runner 的 /etc/docker/certs.d/registry.example.com:5000/ca.crt。托管 runner 改不了这个目录时，使用公网可信证书。

对象存储权限 ​

S3 后端只需要桶级的最小权限：

json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket",
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject"
      ],
      "Resource": [
        "arn:aws:s3:::registry",
        "arn:aws:s3:::registry/*"
      ]
    }
  ]
}

桶要提前建好，registry 不会自动创建。生命周期规则不要删除当前正在引用的对象，最多清理未完成的分片上传。

常见问题 ​

现象原因处理
x509: certificate signed by unknown authority客户端没信任自签 CA把证书放到 /etc/docker/certs.d/<host>:5000/ca.crt 并重启 Docker
http: server gave HTTP response to HTTPS client客户端按 HTTPS 访问，但 registry 没配 TLS配 TLS，或临时在 insecure-registries 里声明（仅限内网）
401 Unauthorizedhtpasswd 路径不对、文件权限不可读或密码错检查 auth.htpasswd.path 和挂载，重新 docker login
推送返回 413反向代理限制了请求体client_max_body_size 0
拉取时被重定向到内网地址后失败registry 把客户端重定向到对象存储内部端点storage.redirect.disable: true
日志持续报 OTLP 连接失败3.x 默认导出 trace 到 localhost:4318设置 OTEL_TRACES_EXPORTER=none
删除 tag 后空间没释放只删了引用，没跑 GC停服后执行 garbage-collect
升级到 3.x 后启动失败配置路径和部分选项变了挂载到 /etc/distribution/config.yml，对照 3.x 配置文档检查

备份 ​

使用 S3 后端时，打开桶版本控制并定期做跨区域复制即可；使用本地磁盘时，停止 registry 后打包数据卷（卷名是 <项目名>_<卷名>，示例项目为 registry）：

bash
docker compose stop registry
docker run --rm \
  -v registry_registry-data:/data:ro \
  -v "$PWD:/backup" \
  alpine:3.22 tar -czf /backup/registry-data-$(date +%F).tar.gz -C /data .
docker compose start registry

运行中直接复制文件可能得到不一致的元数据，恢复后表现为 tag 丢失或 layer 校验失败。备份和 GC 一样，都要求写入停止。
